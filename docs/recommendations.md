# Revision recommendations

A finding says what is wrong. A recommendation, when one is safe, says what the text could become. It is optional, advisory, and never approval.

## The object

A `recommendation` can sit on a blocking finding of a `NEEDS_REVISION` result:

| Field | Meaning |
|---|---|
| `suggested_revision` | The proposed text |
| `reason` | Why |
| `recommendation_basis` | `approved_claim`, `required_disclaimer` or `contextual_rewrite` |
| `original_text` | The draft text it would replace, when there is one |
| `source_reference` | The claim ID the governed text came from. Required for the two governed bases |
| `human_review_required` | Always `true` |

## The three bases

| Basis | Label shown to users | Where the text comes from |
|---|---|---|
| `approved_claim` | Approved wording | The validator's `approved_text`, quoted unchanged. Used when a cited claim is valid but the draft's wording drifted. |
| `required_disclaimer` | Required disclaimer | The validator's `required_disclaimer`, quoted unchanged. A model never writes disclaimer wording. |
| `contextual_rewrite` | Suggested rewrite (not approved copy) | RC2's `suggested_revision`. It may soften an absolute, narrow a scope or clarify. It may not add a claim, number, safety statement, comparison or disclaimer. |

RC3 assembles these in code. RC2 cannot label its own text as approved wording: only the validator's data can produce the two governed bases, and the tool contract rejects a governed recommendation without a `source_reference`.

## When there is no recommendation

- **Unapproved, unknown or uncited claims** get none. Nothing governed can replace a claim that has no approved record, so the finding says to cite an approved claim or remove the statement.
- **`INPUT_REQUIRED`**: nothing was checked, so there are no findings and no rewrites.
- **`VALIDATION_UNAVAILABLE`**: claims could not be checked, so no correction is invented.
- **`READY_FOR_FORMAL_REVIEW`**: may carry advisory findings, never a blocking rewrite. The tool contract rejects a ready result with a recommendation.
- **No safe rewrite**: if any replacement would be a new claim (for example for "safe for everyone"), RC2 leaves it empty.

When two claims in one draft carry different required disclaimers, no single disclaimer recommendation is made.

## Example

From [examples/needs-revision-result.json](../examples/needs-revision-result.json), generated by the workflow's own RC3 and RC4 code:

```json
{
  "type": "claim_wording",
  "severity": "blocking",
  "quote": "OptiThera is indicated for adults with plaque psoriasis.",
  "issue": "CLM-001 is valid for US patients, but the draft drops \"moderate to severe\" and so widens the approved indication.",
  "suggestion": "Change the wording to match the approved claim, or remove the statement.",
  "recommendation": {
    "suggested_revision": "OptiThera is indicated for adults with moderate to severe plaque psoriasis.",
    "reason": "CLM-001 is valid for US patients, but the draft drops \"moderate to severe\" and so widens the approved indication.",
    "recommendation_basis": "approved_claim",
    "human_review_required": true,
    "original_text": "OptiThera is indicated for adults with plaque psoriasis.",
    "source_reference": "CLM-001"
  }
}
```

A contextual rewrite looks the same with `"recommendation_basis": "contextual_rewrite"` and no `source_reference`, for example "OptiThera clears psoriasis fast." becoming "OptiThera may help improve psoriasis symptoms.", shown as "Suggested rewrite (not approved copy)".

## Human review

A person decides whether to use a recommendation, edits the draft and runs the check again. Surfaces only display or copy recommendations; none of them rewrites content automatically. Formal review still follows.
